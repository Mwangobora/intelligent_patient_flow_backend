Set up the project structure for the backend repository named:

```text
intelligent_patient_flow_backend
```

This backend belongs to an Intelligent Patient Flow and Appointment Scheduling System for healthcare facilities.

This task is only for establishing a clean, production-ready Django project structure.

Do not design or implement the database yet.

Do not create:

* domain models
* business migrations
* database relationships
* roles
* permissions
* RBAC logic
* serializers with real business fields
* business APIs
* CRUD endpoints
* business selectors
* business services
* seed data
* fixtures
* default users
* default roles
* default permissions
* placeholder AI models

The goal is to prepare only the backend foundation, application modules, internal folder structure, Docker environment, configuration, testing foundation, and development tooling.

## Automated API startup sequence

The API container must automatically:

1. wait for PostgreSQL
2. wait for Redis
3. run:

```bash
python manage.py migrate --noinput
```

4. run:

```bash
python manage.py collectstatic --noinput
```

5. start Django on:

```text
0.0.0.0:8000
```

No manual migration command should be required after:

```bash
docker compose up
```

or:

```bash
docker compose up --build
```

Use:

```text
scripts/entrypoint.sh
```

The entrypoint must use:

```bash
set -e
```

The script must stop immediately when a startup command fails.

Only the API initialization process should run migrations.

The following services must not independently run migrations:

```text
celery_worker
celery_beat
```

This avoids migration race conditions.

The system must also support:

```bash
docker compose up --build -d
```
